### The Problem with the 6-Round Debate

The engine I built yesterday was too rigid. Every single query — even a simple one — had to go through all 6 rounds: Problem Framing, Cross-Review, Rebuttal, Evidence Check, and Final Synthesis. If I asked "what database should I use for this use case?" and the Architect, Coder, and Security Analyst all said "PostgreSQL," the system would still run every stage of the debate before arriving at the same answer everyone agreed on from round one. That's wasteful in tokens, slow in latency, and unnecessary.

The real model should be: agents collaborate fast by default, and debate only when they genuinely disagree about something important.

---

### Rewriting the Engine: "Collaborate First, Debate on Conflict"

I rewrote `app/agents/debate.py` from scratch into a `CollaborationEngine` class implementing a 4-step protocol:

**Step 1 — Parallel Independent Analysis**

When a query arrives, the selected specialist agents (2 to 4 depending on the query type, selected by the task router) all generate their perspectives simultaneously using `asyncio.gather`. They don't know what the others are saying yet — each is working independently in parallel. This is the fastest possible path to getting multiple expert views.

```python
r1_results = await asyncio.gather(*[analyze_agent(agent) for agent in participating_agents])
```

**Step 2 — Synthesizer Alignment Check**

The moment all parallel responses are collected, the `Synthesizer` agent immediately reviews them all. It's given a prompt that asks it to do one of two things: either merge the responses into a unified final answer if they're fundamentally aligned, or start its response with `CONFLICT_DETECTED:` followed by a description of the exact technical dispute if they genuinely contradict each other.

**Step 3 — Instant Consensus Merge (Fast Path)**

If the Synthesizer finds alignment, it merges the specialist perspectives into a single cohesive, actionable final answer right away. The result comes back with `mode_used = "consensus"` and a confidence score of 0.92. The whole thing finishes in roughly the time it takes for two round-trips to the cloud instead of six.

**Step 4 — Targeted Rebuttal (Conflict Path Only)**

If `CONFLICT_DETECTED:` is detected, the engine fires a targeted rebuttal round. The Adversarial Critic agent receives the conflicting proposals and the identified conflict, challenges the unsafe assumptions, and proposes the safest resolution. Then the Synthesizer runs again on the rebuttal output to produce the final resolved answer. This path returns with `mode_used = "debate"` and a confidence score of 0.88.

I also kept backward-compatible aliases (`DebateEngine`, `run_debate`) so nothing that was already calling the old interface would break.

### Streamlining the Orchestrator

While rewriting the debate engine, I also cleaned up `app/core/orchestrator.py`. The previous version had evaluation and quality scoring loops running synchronously on the critical path — meaning the caller had to wait for those to finish before getting their answer back. I moved that logic off the critical path so the orchestrator returns the final answer, confidence, token count, and latency immediately after the collaboration engine finishes.

### Building the FRIDAY REST API

FRIDAY needed a way to query AI Universe programmatically and to know exactly what agents and models are running inside it. Without this, FRIDAY was hallucinating agent details when asked about AI Universe capabilities. I built three new authenticated endpoints in `app/api/friday_routes.py`:

**`GET /v1/friday/status`**

Returns a live snapshot of AI Universe's operational state:
- `active_agents` — list of all currently registered agent roles (e.g. "Architect", "Coder", "Security Analyst").
- `configured_providers` — list of provider names that have valid non-empty API keys loaded from `.env` (e.g. "Gemini", "Groq", "Mistral"). This is checked live at request time so it reflects the actual `.env` state.
- `available_models` — deduplicated list of all model names currently assigned to active agents.

**`GET /v1/friday/agents`**

Returns the complete agent catalog: all 10 specialists with their `id`, `name`, `role`, `purpose`, `provider`, `model`, `strengths`, and `status`. This is what FRIDAY uses to answer questions about which agent handles what, without guessing.

**`GET /v1/friday/info`**

Returns the platform version, total specialist count, and the unique set of active cloud providers. Useful as a quick health check.

All three endpoints (and the existing `/v1/friday/ask` and `/v1/friday/debate` POST endpoints) require the `X-FRIDAY-API-Key` header, verified by `app/core/security.verify_friday_api_key`. Requests without the header get a `401 Unauthorized`. Requests with an invalid key get a `403 Forbidden`.

### Fixing the Provider Failover Crash

While testing under load, the server was dying with a `NameError: name 'ProviderSwitchingPolicy' is not defined` whenever Gemini timed out. The import was missing from `app/core/orchestrator.py` — `ProviderSwitchingPolicy` and `SwitchReason` from `app/core/policies.py` weren't being imported at the top of the file. So when Gemini hit a timeout and the orchestrator tried to look up the fallback route, it crashed instead of gracefully switching to OpenRouter or NVIDIA.

The fix was straightforward: added the correct import. Now the `PROVIDER_FALLBACK_MATRIX` in `app/core/policies.py` kicks in properly — Gemini → OpenRouter → NVIDIA NIM — and the caller never sees the failure.

### Purging Cerebras Completely

Cerebras had been added earlier as a potential provider but it was causing more problems than it solved — the API was unreliable and the integration was incomplete. I removed it entirely today:

- Deleted `app/providers/cerebras.py`.
- Removed `CerebrasProvider` from `app/providers/__init__.py`.
- Removed `CEREBRAS_API_KEY` from `app/core/config.py` and `.env.example`.
- Removed any Cerebras references from the FRIDAY API routes and provider documentation.

The active roster is now exactly 7 providers — Gemini, Groq, Mistral, OpenRouter, NVIDIA NIM, Cohere, and HuggingFace — and nothing else.
